# 人工验收交付闸门与长任务终点交接

## 范围

- WORKFLOW / BOUNDARIES / REVIEW：双模式交付——默认完整交付须人工确认后再 commit/push/正式 PR；用户声明「每个任务单独提交推送」时允许进行中阶段 commit/push，人工勾选放到整批结束或正式 PR 前。
- `git check` / hook：`待用户验证` 或 `完成` 但人工类 AC 缺 `user_confirmed`/免除时拒绝；`进行中` 有有效证据的阶段提交放行。
- `req pr`：默认仅完整交付；`--allow-stage` 生成阶段 PR（须用户明确阶段交付）。
- `--wait-user` 输出勾选表；`--waive-human` 记录免除。同步 COMMANDS、CHANGELOG、TRIAL 与测试。

## 不包含

- 不改安装/升级；不发版号（记未发布）；人工 AC 用关键词识别，不做复杂 NLP。

- [x] AC-01：WORKFLOW/BOUNDARIES/REVIEW 写明双模式、长任务终点交接与阶段 PR 仅显式允许；COMMANDS 与实现一致。
- [x] AC-02：`git check`/hook 在待用户验证或完成卡人工 AC 未确认/未免除时失败并列出编号；进行中阶段提交有有效证据时通过。
- [x] AC-03：`req pr` 默认拒绝不合规；`--allow-stage` 可生成阶段描述；`--wait-user` 输出勾选表；`--waive-human` 可免除并放行完成卡门禁。
