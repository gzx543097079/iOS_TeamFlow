# 内测试用记录

内测期按真实项目的使用证据调整规则，不在工作流仓库内凭感觉精简措辞。团队成员在真实 iOS 或 Godot 项目中使用 TeamFlow 后，每个任务追加一行；规则改动引用这里的记录作为触发依据，按 [REPAIR](../.agents/teamflow-core/references/REPAIR.md#按证据改进工作流) 执行。

记录放在各自项目之外的共享位置（如团队文档或本仓库的议题），不提交业务项目信息、账号或日志原文。

| 2026-10-14 | 示例 | iOS | Claude Code | 缺陷修复 | 18 | 验收后顺手改了无关文件 | 1 | 轻量改动仍建了卡 |

- **宿主**：Claude Code、Codex CLI、Codex 云端等，区分模型差异。
- **违反的规则**：写 WORKFLOW 或专题的具体条目，例如“到达目标即停”“统一验收”。
- **多余或缺失的步骤**：觉得多余的仪式、反复读取的资料、缺少指引而走弯路之处。

同一问题出现两次以上，或一次造成返工、越权外部动作时，再建卡修改规则。
