# 版本记录

## 未发布

- 完成命令支持 `--confirm-ac` 显式确认指定条件并复用证据；全部条件已确认时不进入空等待。
- 人工证据绑定需求身份与验收语义，拒绝内容变化、跨需求或缺少绑定的复用，不提供旧证据迁移。
- 验证按文档、工具和分发范围选择；项目资料复用已有说明与模块索引，减少重复记录及确认。
- 清理旧需求、日志、历史恢复入口、过期版本说明和历史清理测试；外部资料仅按相关变更复核。

- 验证与完成解耦：未确认 AC 可先执行验证并绑定证据，阶段提交不再要求需求完成；人工 AC 仍须实际确认。
- 同次验证完成仅计算前后两次快照，暂存对象通过单次 Git 批量读取；后续复用仍核对输入。
- 验证报告只保留一份完整快照和结束指纹，输入变化时记录差异。
- 需求读取与指纹共用解析器，只绑定范围、排除项和 AC 条件；标题、排版与进度不使证据失效。
- 启动常规技术决定采用既有约定或默认值，仅边界变化补充架构映射，工程来源与核对时间按章节维护。
- 发布的原生日志验证与打包并行，发布同时等待两项成功；移除无用返回值及固定提示，安装预览改为可读 diff。

## 3.2.0

- 主流程统一为“明确范围 → 实施与随改随测 → 最终验收 → 按明确目标交付”，入口和 README 引用唯一规则源。
- 测试改为自动发现，删除失效的增量选择器及按文案副本维护的断言。
- 待用户验证允许保留未确认 AC；完成状态只能经证据检查进入，需求模板省略重复验证状态与空字段。
- 验证增加 `--requirement`，绑定本次需求和所选 profile 的有效配置；无关需求、其他 profile 与配置排版变化不使证据失效。
- 删除 `release prepare`；准备时直接检查真实环境，保留按 build 的发布事实记录。模块索引与复杂功能文档按需使用。

- 统一验证 CLI，`req complete --profile` 一次执行验证并绑定结构化证据，完成和提交检查自动复用并核对证据。
- 验证配置改为 schema 2，每个 profile 集中定义输入与命令，不保留旧配置兼容。
- 移除重复接入版本清单、导航和缺陷模板；复用项目路径校验与 ZIP 打包实现，同次测试共享 Skill ZIP。
