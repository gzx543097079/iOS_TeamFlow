# 版本记录

## 3.3.4

- App 文案规则增加自然表达与逐条核对方法，要求根据页面事实、用户下一步和产品既有语气写标题、按钮、错误与权限说明；各语言保留相同事实并自然表达。
- README 恢复空目录与 `.agents/skills` 建目录命令，补齐 Git 根目录核对、独立 Skill 包解压、接入诊断和项目验证配置入口。
- 本版更新工作流规范与安装说明，不包含业务 App 文案改写。

## 3.3.3

- App 发布准备增加目标 build 的隐私清单核对，覆盖 App、第三方 SDK、必需原因 API 和 App Store Connect 隐私信息。
- 有广告时按实际网络与归因方案检查 `Info.plist` 的 `SKAdNetworkItems`；AdMob App ID 与 ATT 文案按接入条件分别核对。
- 面向欧洲地区时核对适用的 GDPR 同意流程、拒绝与撤回路径及广告请求行为；AdMob 投放另核对 CMP 与 TCF 接入。
- 同步 App 发布动作模板；本版为工作流规则更新，不代表任何业务 App 已通过发布检查。

## 3.3.2

- 补齐按业务职责划分模块、显式依赖、公开接口和状态所有权规则，无论项目大小默认保持现有 Target/工程结构，未获用户明确要求不拆 Target/Package。
- 明确复用判断与工具类归属，要求抽取后迁移实际调用方并清理无引用的旧实现，避免万能工具类、隐式全局状态和强行抽象。
- 功能模板按需引用同一架构规范，验收复用原需求卡，按实际影响验证依赖、资源和使用方行为；不强制拆包或增加全仓扫描步骤。
- 本版更新工作流规范与模板，不包含业务 App 的模块化重构。

## 3.3.1

- 本版更新工作流规范与验收指引，不宣称业务 App 已实现或通过键盘交互验证。

## 3.3.0

- 提交前检查拒绝验证范围外的暂存新增、修改和删除；人工提交检查只用于文档与记录，并核对暂存快照。
- 人工证据绑定核对范围和内容指纹，新增、删除、修改或旧记录缺少绑定时必须重新实际核对；代码变更不能用人工文字替代已配置的自动验证。
- 补齐需求列表与发布记录最终文件的符号链接检查；占位需求、暂停与取消不能直接完成。
- 新增按需只读 `doctor`、`verify suggest` 和 `req resume`，汇总诊断、验证覆盖建议及恢复摘要，不增加必经步骤或第二套台账。
- App 发布记录强制明确 Bundle ID、环境、完整 commit 和执行结果，区分失败、处理中与完成；同一构建拒绝混用身份。
- 主流程参数细节集中至命令参考，统一普通无障碍与超大字号范围，UI 检查表不重复维护结果；补充按需的数据迁移、敏感信息与外部服务边界专题。
- 非 Git 普通目录不再误用外层仓库文件清单；增加源码仓库验证与分发 profile 的一致性核对。

升级注意：旧人工证据必须重新实际核对并生成源码绑定；`release record` 增加必填的 `--bundle-id`、`--environment`、`--commit` 和 `--outcome`，旧发布文件保留为历史资料，不自动合并。


- 完成命令支持 `--confirm-ac` 显式确认指定条件并复用证据；全部条件已确认时不进入空等待。
- 人工证据绑定需求身份与验收语义，拒绝内容变化、跨需求或缺少绑定的复用，不提供旧证据迁移。
- 验证按文档、工具和分发范围选择；项目资料复用已有说明与模块索引，减少重复记录及确认。
- 清理旧需求、日志、历史恢复入口、过期版本说明和历史清理测试；外部资料仅按相关变更复核。

- 验证与完成解耦：未确认 AC 可先执行验证并绑定证据，阶段提交不再要求需求完成；人工 AC 仍须实际确认。
- 同次验证完成仅计算前后两次快照，暂存对象通过单次 Git 批量读取；后续复用仍核对输入。
- 验证报告只保留一份完整快照和结束指纹，输入变化时记录差异。
- 需求读取与指纹共用解析器，只绑定范围、排除项和 AC 条件；标题、排版与进度不使证据失效。
- 启动常规技术决定采用既有约定或默认值，仅边界变化补充架构映射，工程来源与核对时间按章节维护。
- 发布的原生日志验证与打包并行，发布同时等待两项成功；移除无用返回值及固定提示，安装预览改为可读 diff。

## 3.2.0

- 主流程统一为“明确范围 → 实施与随改随测 → 最终验收 → 按明确目标交付”，入口和 README 引用唯一规则源。
- 测试改为自动发现，删除失效的增量选择器及按文案副本维护的断言。
- 待用户验证允许保留未确认 AC；完成状态只能经证据检查进入，需求模板省略重复验证状态与空字段。
- 验证增加 `--requirement`，绑定本次需求和所选 profile 的有效配置；无关需求、其他 profile 与配置排版变化不使证据失效。
- 删除 `release prepare`；准备时直接检查真实环境，保留按 build 的发布事实记录。模块索引与复杂功能文档按需使用。

- 统一验证 CLI，`req complete --profile` 一次执行验证并绑定结构化证据，完成和提交检查自动复用并核对证据。
- 验证配置改为 schema 2，每个 profile 集中定义输入与命令，不保留旧配置兼容。
- 移除重复接入版本清单、导航和缺陷模板；复用项目路径校验与 ZIP 打包实现，同次测试共享 Skill ZIP。
