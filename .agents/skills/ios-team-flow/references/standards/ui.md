# iOS UI 规范（中文）

版本：1.1.0；键盘规则核对日期：2026-09-28，其他条目核对日期：2026-09-11。适用于 UIKit（OC / Swift）和 SwiftUI。
本规范是基于 Apple 官方资料编写的团队落地标准，不是 Apple 认证文件。区分“审核要求”“Apple 设计建议”“团队默认”；上线前再次核对目标地区、系统版本及最新官方规则。

## 1. 设计基线

- 【Apple 设计建议】优先系统导航、列表、表单、弹窗、菜单、分享和购买组件，遵循所在系统的交互及外观；尊重安全区域、键盘、手势返回和辅助功能。
- 【团队默认】先明确页面目标、主要动作和导航路径，再设计视觉。每页提供内容、加载、空、失败、权限不足等实际适用状态；失败提供重试或恢复入口。
- 【团队默认】先采用系统语义颜色、文字样式和组件默认尺寸。自定义间距可从 4/8/12/16/24/32 pt 取值，但这是项目约定，不是 Apple 强制栅格。设计变量集中管理，避免散落魔法数字。
- 【团队默认】不强制特定 iOS 最低版本；先读取工程部署目标。新系统材质（包括 Liquid Glass）优先用系统组件，使用新 API 时核对可用性并提供必要回退，不把新系统外观强加给旧系统。

## 2. 排版、颜色和适配

- 【Apple 设计建议】使用 Dynamic Type，优先 `.body`、`.headline` 等语义样式；UIKit 用 preferredFont 并启用字体缩放。重要信息在大字号下可换行、滚动，不能截掉价格、购买条件或主操作。
- 【Apple 设计建议】iOS 自定义文字参考默认 17 pt、最小 11 pt；它们不是所有标签必须使用的固定字号。团队避免用最小字号承载购买条件等关键信息。
- 【团队默认】正常正文采用至少 4.5:1 对比度，大字至少 3:1；以 Apple Accessibility 当前尺寸/字重分类及 Accessibility Inspector 实测为准。同时检查深色、浅色、增强对比度和透明背景。
- 【Apple 设计建议】状态同时用文字、图形或形状表达，不只用红绿区分；图片配适当替代说明，纯装饰图不制造朗读噪音。
- 【团队默认】触控热区至少 44×44 pt，图标可小于热区。Apple 当前可访问性文档区分 iOS 默认 44×44 pt 和最小 28×28 pt；本团队采用更宽松易点的 44 pt，不宣称它是所有场景的审核硬门槛。相邻热区避免重叠。
- 支持横竖屏和 iPad 的范围以需求确认结果为准；所支持设备必须验证安全区域、窗口尺寸变化、长文案、RTL 和键盘遮挡。不要用屏幕宽度推算所有布局。

## 3. 操作与无障碍

- 所有用户可见文本和无障碍文本遵守 [多语言文本生成规则](../LOCALIZATION.md)，通过按场景确定层级的点分键从本地化资源读取；布局验证覆盖非开发语言和长文案。
- 按钮说明实际动作，破坏性操作说明后果；有可恢复设计时优先提供撤销。不要阻断系统返回手势或隐藏必要退出路径。
- VoiceOver 验证名称、值、特征、顺序和焦点；滑动等手势有可发现的等效控件。自定义组件支持辅助功能动作。
- 尊重减少动态效果、降低透明度和增强对比度；不要只用声音传达结果。加载期间避免重复提交，加载与失败必须可区分。
- 输入框提供标签、正确键盘类型、焦点切换、校验时机、错误原因；不以 placeholder 代替永久标签。

## 4. 键盘与输入边界

【团队默认】本次新增或修改输入框、搜索、表单、多行编辑、输入弹窗或底部输入栏时，核对实际涉及的以下规则。普通非输入页面不触发；沿用已有适用实现，不默认引入全局键盘管理器或迁移全 App。

### 布局与焦点

- 当前输入框、光标及相关错误提示保持可见；空间不足时允许滚动，并在焦点切换后按需滚动到可视区域。多行编辑优先保证光标附近可见，不强求整个编辑器同时显示。
- 根据当前窗口中的实际遮挡适配布局，不写死键盘高度、不用全屏尺寸直接推算。键盘弹出、收起、输入法和候选栏高度变化时同步布局；支持的旋转、分屏和窗口缩放同样处理。
- 同一区域只采用一套避让机制，避免系统安全区、约束和手工 contentInset 重复补偿。收起时恢复本次调整的间距和滚动指示器，不无条件把原有 inset 或滚动位置清零。
- 焦点有明确所有者。仅在用户开始输入或明确的输入任务入口自动聚焦；在视图已进入当前窗口、转场合适阶段执行，不靠固定延迟，也不在每次渲染或刷新时重新抢焦点。
- 多字段表单按可见、可编辑字段的业务顺序切换“下一项”；最后一项使用合适的“完成”“搜索”或提交动作。列表中的输入使用稳定身份，刷新不能丢失文本、光标位置或焦点。

### 收起、提交与页面退出

- 普通表单提供空白区域点击及适用的滚动收起行为；编辑器或聊天输入按产品场景选择。手势不能吞掉按钮点击、列表选择、文本选择和辅助功能操作，不添加覆盖全屏的透明拦截层。
- 数字或金额键盘没有 Return 键时，提供可发现、可访问的收起入口，例如输入工具栏“完成”。工具栏文案遵守本地化规范。
- 软件 Return、外接键盘和按钮触发的同一业务动作共用校验与防重复提交逻辑。多行编辑的 Return 默认换行，发送单独提供；明确产品约定除外。
- 点击提交应在第一次点击时执行校验，不能只收起键盘而要求再点一次。校验失败保留内容，让首个错误字段及原因可见，按需聚焦；请求失败保留可重试的输入，提交成功后的收起或焦点保留按场景决定。
- 输入弹窗、Sheet、半屏表单在键盘弹出后可滚动，确认和取消入口始终可达。关闭或返回时结束该页面编辑，清理页面持有的监听与延迟聚焦任务；取消交互式返回时不清空内容或强行重置布局。
- 页面已离开、被关闭或不是当前活动输入场景时，异步回调不得再次唤起键盘；重新进入或前后台恢复按明确的页面状态恢复，不无条件自动聚焦。收起键盘本身不代表提交、取消或删除草稿。

### 输入法与设备边界

- 中文等输入法存在组合文本阶段；UIKit 核对 `markedTextRange`，自定义 SwiftUI 输入封装保留等效组合状态。组合未完成时不强制截断、格式化、替换文本或切换焦点，不把中间候选当最终值提交；确认组合文本后再按业务规则校验。
- 粘贴、替换、自动填充及语音输入同样经过输入规则；不能因选择了数字键盘就假定内容必为数字。长度限制按业务定义处理字符，避免截断 Emoji 或组合字符；金额格式尊重当前业务的地区规则。
- 支持 iPad 时覆盖停靠与浮动键盘，浮动键盘不按整屏底部高度整体上推。外接键盘即使没有软件键盘，焦点切换、提交和退出也必须可用；辅助工具栏仍可能造成遮挡。

### 实现选择

- UIKit（OC / Swift）：iOS 15+ 优先 `keyboardLayoutGuide`；浮动键盘按实际需求配置跟随及适应性约束，不假定默认跟随。工程确实支持更低系统时才增加键盘 frame 变化通知适配，转换到当前窗口/容器坐标计算遮挡，并同步系统动画；明确监听生命周期，避免跨窗口或重复响应。
- SwiftUI：优先使用系统键盘安全区避让、可滚动容器和 `FocusState`；按支持系统使用 `scrollDismissesKeyboard` 配置滚动收起。先核对 API 可用性，不为使用新 API 擅自提高部署目标；不在输入内容容器上无条件忽略键盘安全区，也不叠加手工高度补偿。

## 5. 订阅与付费 UI

- 【审核要求】购买前清晰说明获得的内容、订阅期限、价格和适用续订条件；试用说明时长和结束后的收费。不得制造虚假免费、倒计时或节省金额。以 App Review Guidelines 3.1.2 和官方订阅页面为依据。
- 【团队默认】购买按钮、选中套餐、产品 ID、周期、权益、展示价格、购买 API 参数必须来自同一个已验证产品模型。StoreKit 2 使用 `Product.displayPrice`；OC/StoreKit 1 使用产品价格及其 priceLocale 格式化。产品未加载成功时不能用占位价格发起购买。
- 年付折算月价只能作辅助说明，同时明确“按年收取的总金额”；币种、地区和舍入规则必须匹配。节省比例基于真实同币种可比价格计算。
- 首购优惠必须校验适用资格；无试用资格时更新 CTA 和说明。恢复购买、管理订阅、服务条款与隐私政策提供可访问入口；恢复中、取消、待批准、交易失败有独立反馈。
- 付款成功后只根据验证后的交易/权益状态解锁；关闭支付面板或点击按钮不等于成功。不能把 Sandbox 数据当线上价格证据。

## 6. UI 验收记录

对本次涉及页面核对设备/系统、语言、字号、主题、操作及结果；省略不涉及的维度。下面的表仅作检查提示，不要求另填一份；实际结论与证据统一在需求卡引用。

【团队默认测试范围】无明确要求时不验证超大字号（辅助功能的更大字体档位）。只有用户明确要求或已确认需求/验收标准列入时才测试；普通字号与常规字号适配仍按本次改动验证。未要求的超大字号无需填写记录。本约定不改变 Dynamic Type 与现有字号适配的实现建议。

涉及输入时，最低覆盖底部字段聚焦与可见性、下一项切换（多字段）、收起与再次弹出、首次点击提交、校验/请求失败保留内容（涉及时）、退出与再次进入。中文组合输入在支持中文输入的字段中验证；多行、数字键盘、输入弹窗、旋转、iPad 浮动/分屏及外接键盘按页面和支持范围补充。检查重复操作后没有累积间距、跳动、文本丢失或重复提交，普通无障碍核对收起/提交入口和焦点可达性。

将适用的可观察结果写入原需求卡并引用实际运行证据，不复制第二份键盘台账。UI 测试可覆盖主交互；模拟器或自动化未覆盖的输入法候选、浮动键盘和外接键盘场景保留未验证，使用相应实际环境补验。编译、静态规则检查或文档测试不能证明业务页面键盘行为通过。
