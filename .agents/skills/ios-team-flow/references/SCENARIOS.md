# 业务场景试运行

每次重大工作流变更先进行代表性链路演练，再在团队真实项目试运行。源仓库运行 `python3 -m unittest discover -s tests -p test_scenarios.py -v`，临时消费项目通过真实 CLI 接入和运行门禁；自动测试不执行 Codex 需求理解，也不运行 Xcode、StoreKit 或真实设备。

| 场景 | 真实项目执行步骤 | 验收结果 |
| --- | --- | --- |
| 新建 App | 在空目录接入，提出产品需求；检查 PRD 默认 Swift/UIKit/iOS14、导航无 Tab、深色与跟随系统；先确认具体 PRD，再生成工程并实际构建运行 | 确认前无业务工程；确认后配置与 PRD 匹配，权限按实际首版范围配置 |
| 已有 App 增量 | 选择实际有不同框架/系统目标/导航配置的工程，要求修改单一页面；记录 PROJECT-CONTEXT 与构建基线，再执行修改和相关回归 | 保留既有配置；不强制新 PRD、不迁移目录；区分既有失败与新增失败 |
| 大型已有项目再次新增需求 | `.agents/project-modules.json` 已有模块关注路径、入口、影响面及完整提交基准；需求只命中一个普通功能模块 | `module_context.py inspect` 返回命中模块及提交/暂存/未暂存/未跟踪差异；未变化时只读待改符号和必要调用者，变化时返回建议文件；横切路径、未命中或索引失效明确扩大范围 |
| 订阅改动 | 临时分支故意构造月套餐/年文案不匹配，Codex 自审定位问题，修复后复核；同内容重复检查，再变更商品或文案 | 未验证/缺少证据时门禁失败；相同有效指纹复用；新改动需更新审查；真机/平台购买恢复与权益另验 |
| 验收重开 | 指定成员拒绝一个验收项，修复并交其复核 | 保留原失败和确认原文；不以提交代替验收 |
| 升级与发布 | 在真实项目副本演练旧版升级、失败恢复；按 App 发布记录走测试渠道 | 定制保留、恢复可用；只有真实平台证据才推进发布状态 |

将结果存入 `requirements/scenarios/日期-项目.md`，逐项记录：项目与场景、需求编号、工作流 commit/版本、业务 commit/build、步骤、期望/实际、执行人/时间、证据、状态、问题和复核。敏感账号和用户数据脱敏；失败时阻止本次受影响能力推广，修复后重跑受影响场景。

源码演练当前覆盖：空项目接入不创建 App；已有配置保留及失败基线留证；大型项目模块工具记录基准、查询路由、区分四类 Git 变化、横切扩大范围及受控刷新；订阅报告缺证据/未验证被拒绝、修复后的内容生成新指纹。这些测试明确使用夹具，不证明脚本能自动理解业务语义、发现价格错误或 Codex 一定遵循全部规则。

源仓库现提供 App/TeamFlowDemo 内部 UIKit 测试工程，通过 ios-demo profile 执行实际模拟器构建、XCTest 和 UI 测试；它不进入 Skill 分发包。真实产品的 PRD 确认、设备购买、团队验收和平台发布仍需团队业务项目试运行。交付演练工具与规程可以完成，真实项目试运行必须保持 🧪 待验证，不能据此宣称工作流已获生产验证。无明确要求不验证超大字号。

## 新工程生命周期规则的代表性核对

| 请求 | 应采用的执行路径 | 不应据此宣称的结果 |
| --- | --- | --- |
| 新建 Swift/UIKit 或 OC/UIKit 主 App | 已确认范围后读取 APP-LIFECYCLE，生成有效 Scene 配置及窗口绑定，运行两配置实际启动与前后台验证 | 不以只有 SceneDelegate 文件或工具回归通过宣称 App 启动通过 |
| 新建 SwiftUI App | 生成 App/Scene 入口并检查真实窗口和内容，核对成品设置与启动日志 | 不因缺少手写 UIKit SceneDelegate 判失败或重复接管窗口 |
| 既有 App 修改普通页面 | 保持原入口，复用未变的有效证据；发现启动缺陷另按实际范围处理 | 不因本规则无条件迁移整个既有项目 |
| 新工程缺 Xcode / 模拟器 | 生成已获授权的独立部分，启动 AC 保持未验证并列明缺项 | 不用空日志或源仓库 Python 测试代替运行证据 |

以上用于规则路径核对，不表示这些框架组合均完成了新 App 实测。
