# 显式 Git 动作

本专题只在用户明确要求 Git 目标动作时加载。目标授权包含该目标不可缺少且尚未完成的前置步骤，但不向后续或可选动作扩张。

| 用户明确动作 | 允许范围 |
| --- | --- |
| commit / 提交代码 | 暂存本次范围（包括需求卡）、最终核对、创建本地提交 |
| push / 推送当前改动 | 必要时先验证并提交当前范围，再推送明确分支 |
| 打标签 | 创建或推送明确标签；是否推送按用户表述 |
| GitHub Release | 必要时先验证、提交、推送并创建/推送明确标签，再创建 Release；不代表 App Store 发布 |

用户已明确提交目标时，同一需求内的相关小改动可集中实施、统一验收后合并为一次提交，不按文件或修改点拆分提交。复用有效验证证据，提交前只核对本次范围和暂存快照；不把无关改动纳入同一提交。

提交前检查：

```sh
python3 scripts/teamflow.py git check REQ-0001
```

阶段提交不要求需求已完成；提交检查只核对证据及暂存内容，不更改需求状态。默认复用需求卡中的证据，并复核当前输入和暂存快照；也可用 `--result` 指定已有结果。纯文档或记录变更可用 `--evidence "实际核对内容"`。检查通过后，只在 commit 是用户目标或目标的必要前置时执行 commit。工具拒绝所选 profile 输入范围外的暂存文件；仅当前需求卡、验证配置及所引用报告和其日志作为关联证据处理。多类改动应配置覆盖整个提交的 profile，不凭文档测试证明业务代码通过。人工核对仅用于文档/记录，绑定范围和暂存快照，参数见 [命令参考](COMMANDS.md)。暂存范围变化后重新检查。提交消息包含独立尾注 `Requirement: REQ-0001`；提交关联直接从 Git 查询，不写派生文件。

没有明确用户目标时不得安装 Hook、commit、push、打标签或发布。目标已明确时自动完成最小依赖链，不重复索要每个前置的批准；如果前置会纳入目标范围外改动、目标版本不明确或需要不可推断的选择，则先停止询问。
