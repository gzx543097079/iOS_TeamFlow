# iOS UI 规范（强制短清单）

适用于 UIKit（OC / Swift）和 SwiftUI。基于 Apple 资料的团队落地标准，区分「审核要求」「Apple 设计建议」「团队默认/强制」。排版细节、平台控件选用与验收表见 [UI 细则](ui-details.md)；改输入另读[键盘与输入](ui-keyboard.md)；付费墙另读[付费 UI](ui-paywall.md)。**日常实现默认只读本文件**；细则按需加载。

## 强制与默认

- 【Apple 设计建议】优先系统导航、列表、表单、弹窗、菜单、分享和购买组件；尊重安全区域、键盘、手势返回和辅助功能。
- 【团队默认】先明确页面目标与主操作；提供内容、加载、空、失败、权限不足等适用状态；失败有重试或恢复入口。
- 【团队强制】字体、圆角、颜色、间距只在唯一设计变量模块写字面量，业务只引用语义值；`0` 与系统语义样式除外。以 [check_design_tokens](../DESIGN-TOKENS.md) 纳入日常检查。
- 【Apple 设计建议】Dynamic Type / 语义文字样式；重要信息大字号下可换行或滚动，不截断价格与主操作。
- 【团队默认】触控热区至少 44×44 pt；对比度按 Accessibility 实测（含深浅色）。
- 用户可见文本与无障碍文本遵守[共用本地化](../../../../teamflow-core/references/LOCALIZATION.md)与 [iOS 本地化](../LOCALIZATION.md)。
- 破坏性操作说明后果；不阻断系统返回；VoiceOver 名称/顺序可达；尊重减少动态效果。
- 【Apple 设计建议】Tab / 导航栈 / sheet 与系统控件优先；SF Symbols；一个强调色；避免网页移植感（自造导航栏、悬停依赖）。

## 视觉验收（摘要）

- 小改动展示类默认 `--wait-user`，最多两轮；不为纯视觉自跑全量单测/UI 测。行为/契约不得按小改动降测。
- 截图只取改动相关关键页与必要状态；复用已构建产物，见 [UI 评审 · 取得证据](../UI-REVIEW.md#取得证据)。
