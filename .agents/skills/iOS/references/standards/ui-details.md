# iOS UI 细则

承接 [UI 强制短清单](ui.md)。编写或评审需要展开排版、控件选型、动效与完整验收表时再读本文件。

## 1. 设计基线补充

- 【团队默认】先采用系统语义颜色、文字样式和组件默认尺寸。自定义间距可从 4/8/12/16/24/32 pt 取值（项目约定，非 Apple 强制栅格）。
- 【团队默认】不强制特定 iOS 最低版本；先读工程部署目标。新系统材质优先系统组件，新 API 核对可用性并提供回退。

## 2. 排版、颜色和适配

- 【Apple 设计建议】UIKit 用 preferredFont 并启用字体缩放。iOS 自定义文字参考默认 17 pt、最小 11 pt（非所有标签固定字号）；避免用最小字号承载购买条件。
- 【团队默认】正常正文至少 4.5:1 对比度，大字至少 3:1；以 Accessibility 当前分类及 Inspector 实测为准；检查深色、浅色、增强对比度与透明背景。
- 【Apple 设计建议】状态同时用文字、图形或形状，不只用红绿；图片配替代说明，纯装饰不制造朗读噪音。
- 【团队默认】Apple 可访问性文档区分默认 44×44 与最小 28×28；本团队采用 44 pt，不宣称一切场景的审核硬门槛。相邻热区避免重叠。
- 横竖屏与 iPad 范围以需求为准；所支持设备验证安全区域、窗口变化、长文案、RTL 与键盘遮挡。不要用屏幕宽度推算所有布局。

## 3. 操作与无障碍补充

- 按钮说明实际动作；有可恢复设计时优先撤销。
- 滑动等手势有可发现的等效控件；自定义组件支持辅助功能动作。
- 不要只用声音传达结果；加载期间避免重复提交，加载与失败必须可区分。
- 输入框提供标签、正确键盘类型、焦点切换、校验时机、错误原因；不以 placeholder 代替永久标签。涉及输入时按[键盘与输入](ui-keyboard.md#输入验收)核对。

## 4. 平台一致性与常见痕迹

熟练用户应能直接信任界面；常见问题是网页移植感。

- 【Apple 设计建议】2–5 个顶级分区用 Tab 栏（放分区不放操作）；层级用导航栈；独立子任务用 sheet；顶级大标题随滚动收起，深层用行内标题。
- 【Apple 设计建议】开关、分段、步进器、选择器、操作表、上下文菜单、滑动操作用系统控件；设置用分组列表，不堆自定义卡片。
- 【Apple 设计建议】正文和控件用系统字体，品牌字体只用于展示；模糊与半透明用系统材质。
- 【Apple 设计建议】sheet 提供取消与完成并保留下滑关闭，会丢数据时才拦截；不需要打断的任务不用模态。转场沿用系统方向，减少动态效果时改为淡入淡出。
- 【团队默认】动效只表达状态变化，常规过渡约 150–250 ms，不做启动编排。除非需求要求，不用卡片套卡片、渐变文字、彩色粗侧边、彩色光晕、标题上方小标签、「大数字加小标签」指标模板。

## 5. UI 验收记录

对本次涉及页面核对设备/系统、语言、字号、主题、操作及结果；省略不涉及的维度。表仅作检查提示，结论写在需求卡。

【团队默认截图范围】仅截取改动涉及的关键页面和必要状态；共享组件选代表页；未变化时复用有效截图。设备/语言/主题仅在改动影响或验收要求涉及时增加。交互、焦点、提交与恢复仍靠实际操作或测试。构建与截图命令见 [UI-EVIDENCE](../UI-EVIDENCE.md)；验收流程见 [WORKFLOW](../../../../teamflow-core/references/WORKFLOW.md#改动分级)。
