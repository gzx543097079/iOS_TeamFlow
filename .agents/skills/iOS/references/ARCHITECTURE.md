# iOS 架构补充

职责、依赖、复用、抽取迁移和数据恢复统一遵循[共用架构规则](../../../teamflow-core/references/ARCHITECTURE.md)。本文件仅补充原生 iOS 约束。

MVC、MVVM、TCA、Clean 等按确认的模式实施，不统一强制 MVVM。明确采用 MVVM 时，View/Controller 负责渲染、布局和输入转发，ViewModel 处理展示状态、业务意图和结果转换，Model/服务负责数据与业务规则；ViewModel 不持有视图或导航控制器。若实现必须偏离已确认架构，先说明原因、影响和替代方案并取得相应决定，再实施依赖该决定的部分。

### 保持现有工程结构

无论项目大小，默认在现有工程和 Target 内通过业务目录、职责、访问控制及明确接口组织模块。单 Target 项目继续保持单 Target；已有多 Target 项目沿用实际结构。本规则中的“模块化”指逻辑职责划分，不授权拆分 Target、Package、仓库或迁移依赖管理。

只有用户明确要求拆分编译或分发单元时，才另行评估 Target/Package 的必要性、依赖和迁移范围；不能仅因项目变大、功能增多或希望复用就自行拆包。不生成空模块，也不通过批量移动文件代替职责收敛。

目录不提供编译期模块隔离。同一 Target 内仍须通过最小访问级别、清晰入口、代码依赖核对和受影响行为测试维护边界；不宣称不同目录之间已获得编译器强制隔离。保持已有工程生成配置、资源和依赖方式，本次确需移动内部文件时同步核对 Target 成员关系与资源引用。
