# 产物存放

适用于实施中产生的非工程文件：方案设计文档、设计原稿与参考图、UI 预览、报告、生成素材和一次性脚本等。业务代码、工程配置、测试与运行时资源按工程结构放置，不适用本规则。

## 原则

- 产物保存在当前项目内并按用途分类；首次写入前创建目录，不散落项目根目录，也不把桌面、下载或项目外临时路径作为存放位置。
- 已有工程沿用其目录约定，并把约定入口记入 `PROJECT-CONTEXT.md`；没有约定时按下表默认布局。
- 命名表达内容与用途；只保留有用途的产物，过期产物删除或在需求卡记录保留原因。

| 产物 | 默认位置 |
| --- | --- |
| 需求方案设计文档 | `docs/design/REQ-〈编号〉-〈主题〉.md`，需求卡引用；`requirements/` 只由 `req` 命令写入需求记录 |
| 设计原稿、参考图与 UI 预览 | `docs/design/〈来源或需求〉/`，就近记录来源与使用位置 |
| 生成素材（AI 图片、图标草稿、音频样本等） | `docs/design/generated/〈主题〉/`，标注生成方式；工程采用后迁入运行时资源并保持引用 |
| 调研、分析与评审报告 | `docs/reports/〈主题〉.md`，需求卡或交付说明引用 |
| 发布与宣传素材（商店截图、宣传图、文案草稿） | `docs/release/〈版本或主题〉/` |
| 一次性脚本（数据处理、批量修改、调试辅助） | `scripts/one-off/〈主题〉/`，注明用途与结果；长期使用时迁入工程脚本并纳入验证 |
| 构建与导出产物（安装包、导出包） | 平台构建或导出目录（如 `build/`、`dist/`），不作为交付依赖提交 |
| 验证截图、日志与临时产物 | 项目内已忽略目录（如 `logs/`），证据引用见 [CHECKS](CHECKS.md) |

表外产物按最接近的类别归档，由引用方说明用途；确实无法归类时放 `docs/artifacts/〈需求或主题〉/`。

运行时资源（图标、音频、字体、场景资源等）放入平台资源目录并保持工程引用一致，位置按当前模式 Skill 专题执行，不适用上表。来源与质量限制按用户当前要求记录，不用无关素材替换。
