# 验证与命令

主流程与停止条件见 [WORKFLOW](WORKFLOW.md)。首次使用环境或环境变化时，低成本核对工具、依赖、Scheme/Target、设备及目标所需账号；命令来自实际工程或 CI，不猜测，也不把完整构建当预检。

## 配置与运行

首次配置项目的真实验证命令：

```sh
python3 scripts/teamflow.py verify init
# 编辑 .agents/project-checks.json
python3 scripts/teamflow.py verify run --profile change --requirement REQ-20260101-a3f9
```

配置只维护 `profiles`：每项就近定义 `checks` 和可选 `inputs`，省略输入时使用 Git 可见文件。`"extends": "其他 profile"` 继承其输入与检查，自身 `checks` 追加或同名覆盖，适合“发布验证 = 日常验证 + 打包”。检查使用 argv 数组，无 shell 展开；所选 profile 的每项均为必跑。测试已包含构建时不重复 build。

```json
{
  "schema_version": 2,
  "profiles": {
    "change": {
      "inputs": ["App", "scripts/test_app.py"],
      "checks": {
        "tests": {"argv": ["python3", "scripts/test_app.py"], "timeout_seconds": 900}
      }
    }
  }
}
```

示例路径须替换为项目实际文件与命令；命令复用可放在项目脚本中。

收尾前确认本次受验证输入稳定、用户改动已隔离，然后运行匹配范围的 profile。同批相关小改动在结束后统一检查，按 [主流程](WORKFLOW.md#实施与验收) 复用有效证据；失败后修复并重跑必要验证。

## 验证强度与结果输出

小改动同时按影响范围和风险判断，不以文件数或代码行数单独判断。局部文档措辞、链接或简单展示调整可选择能覆盖改动的快速检查；涉及支付、认证、数据迁移、共享状态或工程配置时，按实际影响补齐必要验证，即使只改一行也不自动降低强度。

快速检查使用项目已有或按实际需要配置的最小有效 profile：例如文档链接检查、相关单元测试，涉及编译或 UI 时补齐必要构建或运行核对。profile 名以项目配置为准，不假定存在 `quick`；选定 profile 的必跑项仍全部执行。正式分发仍执行对应发布验证。

面向用户的验证结果摘要只返回“通过”或“失败”，不逐项展开命令、耗时与日志。未执行的检查明确标为“未验证”，不能当作通过或测试失败。完整日志、输入快照和证据由工具保留，工具的结构化输出继续供证据绑定与诊断使用；需要用户处理的阻塞仍说明必要原因。

## 证据

- **运行**：`verify run` 与 `req complete --profile` 在 `logs/project-checks/<运行编号>/` 保存原始日志和结果，只作本地记录（`setup` 已忽略该目录）。失败、超时、工具缺失或运行期间输入变化均不算通过。
- **指纹**：覆盖所选 profile 的命令、工作目录、超时、输入范围及输入文件内容（含增删与可执行位）；其他 profile 与 JSON 排版不影响。绑定需求时另加需求语义：范围、不包含和按编号排序的 AC 文字；标题、排版、状态、勾选、证据摘要和决策记录不影响。
- **摘要**：完成时写入卡片头部；之后 `req complete`、`git check`、`doctor` 都按摘要重新计算当前指纹核对，不读取日志。提交检查另核对暂存快照，见 [BOUNDARIES](BOUNDARIES.md#显式-git-动作)。
- 不绑定需求的独立检查结果不能直接用于 `req complete`。配置输入应指向实际工程，避免纳入全部历史资料。
- 工具测试不能代替真机、视觉、账号、购买或平台验证；人工 AC 按主流程保留待验证。
- 检查命令是受信任的项目代码，并非文件系统或网络沙箱，涉及时遵循 [敏感信息与外部服务](BOUNDARIES.md#敏感信息与外部服务)。

## 命令参考

### 验证与完成

`req complete REQ-20260101-a3f9 --profile change` 运行所选验证，并把证据摘要写入卡片头部。`--result logs/project-checks/运行编号/result.json` 绑定本地已有结果；不传证据参数时先按卡片摘要重新计算指纹复核，不读取日志；摘要缺失或失效且项目已配置验证时，自动选择覆盖全部改动、检查项最少的 profile 运行（输出标注“按改动自动选择”），没有单个 profile 覆盖时报出未覆盖文件且不改卡片。三种证据来源 `--profile`、`--result`、`--evidence` 互斥。

`--confirm-ac AC-01` 可重复，表示已经按实际证据核对指定条件，不根据测试结果推断人工 AC。未知编号、证据无效或验证失败均不更改卡片。未指定条件保留原状态。

未完成 AC 保持进行中；只有明确等待用户确认才加 `--wait-user`，全部 AC 已确认时仍直接完成。阻塞、取消须按用户明确恢复决定执行 `req state REQ-20260101-a3f9 --state 进行中 --reason "恢复依据"`，再验收。草稿允许占位，验收拒绝占位内容。

### 输出

所有命令默认输出几行简短摘要：验证只报“通过/失败”，失败时附失败项与本地日志路径；需求命令报告状态、进度、剩余 AC 和下一步。追加 `--json` 输出完整结构，供脚本或诊断使用。

### 状态

```sh
python3 scripts/teamflow.py req state REQ-20260101-a3f9 --state 阻塞 --blocked 待确认 --reason "等待选择登录方式"
python3 scripts/teamflow.py req state REQ-20260101-a3f9 --state 进行中 --reason "用户已选择短信登录"
```

`--blocked` 取值 `待确认`、`外部`、`暂停`，只用于阻塞。恢复时清除阻塞类型、原因和排队标记，并在“决策与异常”追加记录。

### 人工证据

仅在适用自动检查不存在且实际人工核对足够时使用：

```sh
python3 scripts/teamflow.py req complete REQ-20260101-a3f9 \
  --evidence "实际核对结论及可定位证据" --evidence-input docs --confirm-ac AC-01
```

`--evidence-input` 可重复，只允许项目相对文件/目录；省略时绑定整个项目的 Git 可见输入。始终额外绑定本需求语义。绑定包含文件内容、增删和可执行位；目录内新增文件也使证据失效，忽略生成证据和其他需求记录。显式文件范围外的变化不会使证据失效，因此范围必须覆盖实际影响面。

需求语义或文件快照变化、旧证据缺少源码绑定时，不迁移旧结论，重新实际核对并提供新的 `--evidence`。标题、排版、进度和证据更新不影响需求语义绑定。项目已配置检查且人工范围内存在代码变更时，使用自动证据并通过 `--confirm-ac` 确认人工条件；人工文字不能替代必要自动验证。

`git check` 的人工证据仅支持 `.md`、`.rst`、`.txt` 文档/记录，仍核对文件范围和暂存快照；这些扩展名不是语义证明，脚本或业务数据即使使用文本扩展名也必须执行实际适用检查。

### 只读辅助

```sh
python3 scripts/teamflow.py doctor
python3 scripts/teamflow.py verify suggest
python3 scripts/teamflow.py req status REQ-20260101-a3f9
```

- `doctor` 汇总接入、验证配置与输入、占位卡片、失效证据及已启用模块索引，默认每项一行，`--json` 输出完整结构。已完成需求仅证据失效时列为历史提示，不计入需处理。发现需处理项退出 1，不执行修复或项目检查；不因工具仓库缺少 Xcode 强制阻塞。
- `verify suggest` 列出相对 HEAD 的暂存、未暂存和未跟踪改动、各 profile 覆盖和遗漏路径，以及 `req complete` 会自动选用的 profile。只按路径建议，不能判断某项测试足以验证业务语义；不执行检查。
- `req status` 汇总状态、进度、证据有效性与问题、剩余 AC 和下一步，`--json` 另含范围、AC 与决策记录。不修改状态，不自动恢复阻塞或取消，不为已完成需求扩张交付。

这些命令按需使用，不成为每个需求的强制前置。诊断旧完成卡的证据失效只提示当前证据不可复用，不自动重开历史需求。
