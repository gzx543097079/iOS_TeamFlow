# 代码关系图

关系图是按任务维护的代码导航资料，不是运行时事实或完整调用图。只在跨模块追踪、已有入口难以命中、代码分散或用户要求时生成或扩展；单点问题直接定位即可。优先复用项目已有架构图、语言服务器和模块索引，不要求安装工具、全仓扫描或引入图数据库。`PROJECT-CONTEXT.md` 只链接已有资料；机器可维护的模块职责、路径、入口、依赖与调用方仍以 [模块索引](MODULE-CONTEXT.md) 为准，不复制第二张模块表。

## 建立与使用

- 新项目：先看已有说明、工程配置与实际入口；尚未实现的结构只作为设计方案，不画成现状。随着代码落地，在确有跨模块查找需要时从入口和关键流程建立局部图。
- 已有项目：先查现有资料和索引，按当前需求选择目标、入口与边界；围绕实际调用或数据路径从小范围逐步扩展，不以目录结构推断依赖。大型或混乱工程先搜索页面文案、错误、接口、路由、符号、配置及资源，再确认实际使用的实现；同名实现须区分 Target、平台与运行条件。
- 图优先记录有助定位的节点与有向关系：入口、模块/文件/符号、调用或引用、数据与状态流、接口、配置和跨平台桥接，以及必要的测试入口。每条关系注明类型、方向、条件和可定位的源码或配置依据；只画与范围有关的内容。
- 静态搜索、语言服务器或现有索引给出候选，结合代码、定向测试、可复现日志或运行跟踪核实。反射、动态分发、依赖注入、事件、异步回调、生成代码和运行时配置可能使静态结果不完整；无法确认时标为待核实并写明原因，不把未找到关系当作不存在。图过期、未命中或来源冲突时回到源码并扩大搜索。
- 长期资料放项目现有架构文档或其约定位置；不存在约定时与项目架构资料相邻存放，以 Markdown 表格或 Mermaid 等项目已有格式表达，复杂图按模块或流程拆分。一次性分析留在需求记录或按项目产物约定存放，不为临时排查新建长期图。不得写入凭据、用户数据或原始敏感日志。
- 每张图标明范围、平台/Target、源码依据、核对日期及必要的版本或 commit；区分已证实与待核实关系。查阅时只读相关局部，再核对本次修改涉及的源码和调用方；图不替代测试或验收。

## 增加、更新与减少

- 增加：新业务流程或跨模块关系落地，现有图无法回答重复出现的定位问题，或本次调查确认了后续有用的关系时，增补相应局部与依据。
- 更新：入口、调用、状态流、接口、路径、配置、Target 或桥接发生变化时，随相关改动核对并更新受影响局部；重命名或移动同步修复引用。模块索引按自身规则维护，图只引用它。
- 减少：代码、模块或路径删除，关系不再存在，范围合并或图中重复、过细的内容失去导航价值时，确认源码后删除或合并对应节点与边；仍有使用方的关系不能只因当前任务未使用就删除。
- 失效：来源变化、长期未核对、证据冲突或无法确定适用范围时，标注待核实并重新核对；不能核实时保留限制或移除误导内容，不静默当作准确。仅在实际核对相关内容后更新日期，不为每次任务刷新全图。
