# 缺陷修复与工作流改进

主流程、状态与授权见 [WORKFLOW](WORKFLOW.md)；本专题在修复缺陷或改进工作流时加载。

## 缺陷修复

新缺陷创建：

```sh
python3 scripts/teamflow.py req create --bug --title "缺陷标题"
```

复现、根因和失败尝试有事实时补充到原卡，省略空字段。优先记录可复现条件、期望、实际和影响，再定位根因。能安全复现时先保留失败证据；修复后重跑原失败场景及受影响回归。环境或历史失败与本次新增问题分开。

同一缺陷复发时续接原卡并重开受影响 AC；独立根因另建卡。只有实际发生的重要失败、尝试、修复和复核写入“决策与异常”，不另建台账。

## 按证据改进工作流

只在已复现流程缺陷、重复返工、重复无效操作或用户明确纠正工作方式时使用。未经验证的猜测、单次网络波动和个人偏好不固化为通用规则。

1. 在当前需求卡写明触发、范围和可观察 AC。
2. 定位最小根因，优先修正旧规则或工具，不叠加第二套台账。
3. 保留修复前失败与修复后通过的同一场景；纯措辞调整不增加无行为价值的测试。
4. 使用可比较的命令次数、文件数量、耗时或实际 token 数据说明效率变化；没有可靠数据不承诺比例。
5. 改进失败或成本高于收益时停止并撤销本次可归因改动。

流程改进授权不包含 commit、push、发布或任何 App 外部动作。删除兼容代码或旧入口必须由本次范围明确允许。
